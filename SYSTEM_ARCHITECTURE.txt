================================================================================
SERVICE ARCHITECTURE
================================================================================

LINUX/RASPBERRY PI (systemd):
------------------------------

    System Boot
        │
        ▼
    systemd starts
        │
        ▼
    power-monitor.service
        │
        ├─ WorkingDirectory: /path/to/project
        ├─ User: pi
        ├─ ExecStart: python3 -m src.background_monitor
        ├─ Restart: always
        └─ RestartSec: 10
        │
        ▼
    BackgroundMonitor
        │
        ├─ Initialize GPIO
        ├─ Connect to database
        ├─ Start monitoring loop
        └─ Log to journal
        │
        ▼
    Continuous Operation
        │
        ├─ Poll GPIO every 0.5s
        ├─ Detect state changes
        ├─ Record events to DB
        └─ Log activities
        │
        ▼
    On Failure
        │
        └─ systemd auto-restarts


WINDOWS (Windows Service):
---------------------------

    System Boot
        │
        ▼
    Windows Service Manager
        │
        ▼
    PowerMonitorService
        │
        ├─ Service Name: PowerMonitorService
        ├─ Display Name: Power Monitor Service
        ├─ Start Type: Automatic
        └─ Recovery: Restart on failure
        │
        ▼
    BackgroundMonitor
        │
        ├─ Initialize (simulated GPIO)
        ├─ Connect to database
        ├─ Start monitoring loop
        └─ Log to service.log
        │
        ▼
    Continuous Operation
        │
        ├─ Monitor database/simulation
        ├─ Record events to DB
        └─ Log activities
        │
        ▼
    On Failure
        │
        └─ Service Manager auto-restarts


================================================================================
DATA FLOW
================================================================================

1. STATE CHANGE DETECTION:
   -----------------------
   Power Source → GPIO Pin → GPIOReader.read_pin()
                                    │
                                    ▼
                            State comparison
                                    │
                                    ▼
                            Debounce check
                                    │
                                    ▼
                            Callback trigger


2. EVENT RECORDING:
   ----------------
   Callback → BackgroundMonitor._handle_state_change()
                                    │
                                    ▼
                            Create event data
                                    │
                                    ▼
                            DatabaseWriter.record_event()
                                    │
                                    ▼
                            SQL INSERT
                                    │
                                    ▼
                            MySQL Database


3. EVENT RETRIEVAL:
   ----------------
   GUI Request → DatabaseReader.get_events()
                                    │
                                    ▼
                            SQL SELECT with filters
                                    │
                                    ▼
                            MySQL Database
                                    │
                                    ▼
                            Format results
                                    │
                                    ▼
                            Return to GUI


4. POWER OUTAGE DETECTION:
   -----------------------
   EB State Change (1→0) → BackgroundMonitor
                                    │
                                    ▼
                            Log warning
                                    │
                                    ▼
                            DatabaseWriter.start_outage()
                                    │
                                    ▼
                            Insert into outages table
                                    │
                                    ▼
                            (Optional) Send notification

================================================================================
MONITORING & LOGGING
================================================================================

LOG LEVELS:
-----------
DEBUG   → Detailed GPIO readings, all state checks
INFO    → State changes, events recorded, service status
WARNING → Power outages, connection issues
ERROR   → Database errors, GPIO failures
CRITICAL → Service crashes, fatal errors


LOG DESTINATIONS:
-----------------
Linux/RPi:
  - systemd journal (journalctl -u power-monitor)
  - monitor_service.log (file)
  - Console (when run manually)

Windows:
  - service.log (file)
  - Windows Event Log
  - Console (when run manually)


MONITORING POINTS:
------------------
1. Service Status
   - Is service running?
   - When did it start?
   - Any recent restarts?

2. GPIO Status
   - Current pin states
   - Last state change times
   - Change frequency

3. Database Status
   - Connection status
   - Event count
   - Last event timestamp

4. System Health
   - CPU usage
   - Memory usage
   - Disk space


================================================================================
SECURITY CONSIDERATIONS
================================================================================

1. DATABASE SECURITY:
   ------------------
   - Use strong passwords
   - Limit database user permissions (read/write only to ebpc database)
   - Enable MySQL authentication
   - Consider SSL/TLS for remote connections

2. GPIO SAFETY:
   ------------
   - Use optocouplers for electrical isolation
   - Never exceed 3.3V on GPIO pins
   - Use current-limiting resistors
   - Proper grounding

3. SERVICE SECURITY:
   -----------------
   - Run as non-root user (pi) on Linux
   - Limit file permissions
   - Secure config.json (contains DB password)
   - Regular security updates

4. NETWORK SECURITY:
   -----------------
   - Firewall rules for MySQL port
   - VPN for remote access
   - Secure SSH access
   - Regular backups


================================================================================
SCALABILITY
================================================================================

CURRENT CAPACITY:
-----------------
- Inputs: 3 (EB, GEN1, GEN2)
- Polling: 0.5 seconds
- Events: Unlimited (database size dependent)
- Performance: <1% CPU, 50-100 MB RAM

EXPANSION OPTIONS:
------------------
1. More Generators:
   - Add more GPIO pins
   - Update pin_config in gpio_reader.py
   - No other changes needed

2. Multiple Raspberry Pi:
   - Each Pi runs independent service
   - All write to same/different databases
   - Central GUI can query multiple databases

3. Remote Monitoring:
   - Expose MySQL over network
   - VPN for secure access
   - Web dashboard (future enhancement)

4. High Availability:
   - Database replication
   - Multiple monitoring nodes
   - Failover configuration
